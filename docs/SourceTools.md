# Source Tools 集成使用指南

适用：BomberStudio Blender Bridge **1.1.0**。内置来源：用户提供的 **Blender Source Tools 3.4.3**。

## 1. 安装哪个包

安装 `BomberStudio_Blender_1.1.0_Universal.zip`，不用另外安装 `io_scene_valvesource`。

- Blender **4.1 及更新版本**：启用 BomberStudio 时加载内置 Source Tools；已有已启用的独立版时复用它。
- Blender **2.79～4.0**：同一 ZIP 的原有 BomberStudio 功能继续可用，但不加载这份要求 4.1 的内置 Source Tools。
- 若旧 Blender 中已启用它适配的独立 Source Tools，可由集成入口复用；旧独立版本的全部参数组合未逐版实测。
- 已验证的准确版本及平台见 [兼容记录](./兼容验证.md)。这里的最低版本不是对未来所有版本的保证。

安装操作：

1. 保存当前 `.blend`，关闭其他正在操作此模型的窗口。
2. Blender 4.1：编辑 → 首选项 → 插件 → 安装；4.2+：从磁盘安装。
3. 选择上面的 **Universal ZIP**，不要解压、不要选 GitHub 自动生成的源码 ZIP。
4. 搜索并启用 **BomberStudio Blender Bridge**。
5. 回到 3D 视图，按 **N**，打开 **BomberStudio** 标签。
6. 展开 **Source Tools · SMD / VTA / DMX / QC**。
7. 确认状态为“内置 Source Tools 3.4.3 已启用”或“复用已启用的独立 Source Tools”。

更新旧 BomberStudio 时，可以使用“检查版本更新 → 从本地 ZIP 安装更新（保留备份）”，然后保存工作并重启 Blender。不要同时启用 BomberStudio 的 Legacy 与 Extension 两个副本。

## 2. 已经装过独立 Source Tools 怎么办

不必删除原来的文件夹：

1. 若独立版已启用，BomberStudio 直接调用它，不重复注册 `Scene.vs` 和 SMD 导入 / 导出算子。
2. 停用 BomberStudio 不会停用或卸载该独立版。
3. 想从内置版切换到独立版：先在 Source 面板点击 **停用内置副本（切换独立版前）**，再在首选项启用独立版。
4. 想从独立版切回内置版：先在首选项停用独立版，然后在 BomberStudio 面板点击 **启用 / 重试 Source Tools**。
5. 切换后最好保存首选项并重启 Blender，避免同一个文件会话保留多个版本的 RNA 属性。
6. 若出现“检测到不完整或冲突的 Source Tools 注册”，先停用重复副本并重启，再启用一个提供者。插件不会擅自卸载其他插件。

仅把原始 `io_scene_valvesource` 放在开发目录里，不代表它已在 Blender 中启用。

## 3. 导入 SMD 模型

1. 在 Source 面板点击 **导入 Source 模型 / 动画**；快速访问和文件 → 导入中也有入口。
2. 选择 `.smd` 文件，可按 Ctrl 多选。不要把编译后的 `.mdl` 当作 `.smd` 选择。
3. 右侧选项：
   - **导入动画**：默认开启。
   - **为导入模型创建集合**：默认开启，保留 Source 的集合导出单元。
   - **骨架处理**：导入独立角色选 **新建骨架**；给现有角色附加内容时选 **合并到现有骨架**；已有骨架只接受匹配名称时选 **验证现有骨架**。
   - **向上轴**：默认 Z，与文件实际轴向保持一致。
   - **根据 QC 创建相机**：仅在导入带相关数据的 QC 时需要。
4. 点击导入。
5. 在大纲视图检查集合、网格与骨架；在对象数据里检查 UV 与顶点组。
6. 切到材质预览检查图片。SMD 的材质名不等于图片已自动准备好，缺失图片需要另行指定。

Source 入口保留原导入器的材质处理，不会自动把 Source 材质解释成 BomberStudio 的 Unity 材质旁文件，也不负责完整解析 VMT/VTF 材质网络。

## 4. 导入 SMD 骨骼动画

1. 先导入参考模型及正确骨架。
2. 保存 `.blend`。需要自动备份时，在 **设置与诊断** 勾选“修改前保存 .blend 回滚副本”（默认关闭）。
3. 选中目标骨架，再导入动画 `.smd`。
4. 保持 **导入动画** 开启，骨架处理选 **验证现有骨架**。
5. 打开 Dope Sheet / 动作编辑器，检查骨架 Action 和帧范围；拖动时间轴确认实际动作。

动画导入成功可能 **新增 0 个对象**，这是正常情况；集成层不会再误报“导入器未创建物体”。不匹配的骨名请按原导入器日志检查。

## 5. 导入 VTA 口型 / 形态键

1. 先导入与 VTA 对应的参考 `.smd` 网格。
2. 选中这个网格，不要选错为另一套拓扑的角色。
3. 建议先保存 `.blend` 或启用自动备份。
4. 点击导入，选择 `.vta`；骨架处理通常使用 **验证现有骨架**。
5. 在对象数据 → 形态键查看 Basis 及新增口型。
6. 把某个口型值从 0 调到 1，检查顶点确实变化，而不只是出现一个空名称。

VTA 依赖对应网格的顶点信息。不同模型、不同拓扑的文件不是可直接互换的口型库。自动备份开启时，VTA 导入前会把副本写入临时目录的 `backups/`。

## 6. 导入 DMX

1. 使用同一个 Source 导入入口选择 `.dmx`。
2. 独立模型选择新建骨架；附加内容按实际骨架选择验证 / 合并。
3. 导入后分别检查网格、骨骼、顶点组、UV、形态键和动画。
4. 内置数据模型模块处理其支持的 binary / keyvalues2 格式，不把任意一种 DMX 变体视为等价格式。

回归样例实际覆盖 binary 编码 5 / model 18 的网格、骨架、权重和形态键往返；不是所有 Source 游戏全部 DMX 变体都已验证。

## 7. 导入 QC / QCI

1. 保留 QC、QCI 和它们引用的 SMD / DMX / VTA 相对目录，不要只复制一个 QC 文件。
2. 导入 `.qc`，或按需要选择 `.qci`。
3. Source Tools 会读取模型描述及引用文件；缺失引用时查看 Blender 信息日志。
4. 检查引用的网格和动画是否生成。

**导入 QC ≠ 编译 QC，也不会自动解包 MDL。** 编译需要另行配置游戏 SDK 的 `studiomdl`；本版没有附带 SDK，没有在测试期间执行用户的游戏编译器。

## 8. 把 BomberStudio 导出的模型转换为 Source 文件

1. 先用 **导入 BomberStudio 模型** 导入 FBX，完成材质、骨架和权重检查。
2. 保存工作；如需做材质图集、名称整理或口型处理，先完成相应操作。
3. 打开 Source 面板。
4. 设置 **Source 导出目录**，例如 `D:\ModelWork\source_export`。尚未保存 `.blend` 时使用绝对路径。
5. 选择 **SMD** 或 **DMX**，并确认向上轴。
6. 点击 **刷新导出列表**。
7. 检查要导出的网格 / 集合在列表中已勾选。
8. 选中网格或骨架，点击 **导出选中**；要导出所有启用的导出单元时使用 **导出整个场景**。
9. 打开输出目录检查实际生成文件，再在一个干净 Blender 场景重新导入确认。

**选择的是 Source 导出单元**：如果选中网格属于启用的 Source 集合，按该集合导出，集合中其他启用成员也可能包含在同一文件中。这与 Source Tools 原生导出菜单一致；需要逐物体导出时调整集合的导出 / mute 设置，而不是依靠只选中一个成员来排除其他成员。

导出名称与子目录来自物体、集合以及 Source Tools 设置，不是 FBX 文件名输入框。对同名文件反复导出会按原导出器行为覆盖，请用不同输出目录保留版本。

## 9. SMD 与 VTA 导出

1. 导出格式选择 **SMD**。
2. SMD 类型按目标选择 **Source** 或 **GoldSrc**。
3. 选中导出单元并导出。
4. 有形态键的网格通常会一起输出 `.vta`，不需要把文件扩展名手工改成 VTA。
5. 核对 SMD 的网格与骨架、VTA 的口型变化。

集成版在烘焙参考网格时固定 Basis，避免非零口型值混入基础网格；原场景由导出器的撤销事务恢复。Blender 5.2 的形态键默认值差异已用实际顶点位移测试覆盖。

## 10. DMX 导出

1. 格式选择 **DMX**。
2. 按目标游戏需要设置 **DMX 编码** 与 **模型格式**。测试组合是编码 5、模型 18，不应把这个组合当作所有游戏的默认答案。
3. 设置材质目录；需要可读的文本文件时勾选 **文本 DMX**。
4. 执行导出并重新导入检查。
5. 更完整的控制项，包括骨架动画筛选、集合自动合并、flex 控制器、顶点动画和 Source 引擎路径，仍位于原生 Source Tools 的属性面板。

## 11. 完整 Source Tools 界面在哪里

除了 BomberStudio N 面板的快捷入口，内置提供者还保留：

- 文件 → 导入 / 导出中的 Source 原生菜单。
- 属性编辑器 → 场景的 **Source Engine** 导出与 QC 编译设置。
- 物体 / 集合 / 骨架等对应的导出设置。
- 形态键依赖、纠正形态驱动、flex 控制器与顶点动画工具。
- 文本编辑器的 UUID 工具。

这些高级能力来自保留的原生提供者。没有真实 SDK / 游戏资产的项目不冒充为已完成游戏内验收。

## 12. 日志、更新、回滚

- 状态和错误：临时目录 `bomberstudio.log`，以及 Blender 信息日志 / 系统控制台。
- 最近 Source 导入：`last-source-import.json`，包含所选文件路径、提供者类型和新增对象数。
- 自动模型备份：启用备份选项后，写入 `backups/`；失败导入可能已部分改变现有骨架，可重开保存的副本恢复。
- 缺失文件在修改场景前检查；原生导入器发生解析异常时恢复“导入后进入编辑模式”偏好。
- 内置 Source Tools 的检查更新按钮转交 **BomberStudio 集成包**，不再执行原独立插件的覆盖更新器。
- 集成包只在主动检查时联网；不后台下载或静默替换源码。
- 独立安装版继续由它自身管理，BomberStudio 不修改它的文件。
- 软件版本回滚使用 BomberStudio 的“还原上一次插件备份”，然后重启 Blender。
