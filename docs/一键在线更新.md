# 1.2.0：检查后直接更新插件

## 操作流程

**手动检查更新 → 立即更新至目标版本 → 确认 → 下载和校验 → 自动备份安装 → 保存工作并重启 Blender。**

1. 展开 **BomberStudio → 检查版本更新**。
2. 仓库默认是 `Hoshino486/BomberStudio_Blender`，也接受完整 GitHub 地址；仍可自定义。
3. 点击 **手动检查更新**。网络检查在后台线程运行，线程不访问 Blender 数据。
4. 检查结果有更新且 Release 有合适附件时，显示 **存在可用更新！** 和 **立即更新至 X.Y.Z**。
5. 点击立即更新；确认框会列出仓库、版本和附件。确认后才开始下载，不需要自己浏览网页找 ZIP。
6. 下载时显示进度，可点击 **取消** 或按 **Esc**。取消可能需要等待当前网络读取结束，单次读取超时为 15 秒。
7. 下载完成后依次校验 SHA256、ZIP 结构、Python 语法和包内版本；通过后保留旧版，再替换插件代码。
8. 完成时显示红色警示样式的 **请保存工作并重启 Blender 完成更新**。
9. 保存 `.blend`，关闭并重新启动 Blender；检查“当前版本”和关键功能。

不会自动关闭 Blender、自动保存场景或热重载插件。
安装和文件复制阶段在主线程短暂执行；检查和下载在后台进行。
重启之前运行的仍是原来已经加载的代码，不要把磁盘替换完成当作当前进程已经升级。

## 第一次怎么获得这个功能

1.1.x 只有版本查询和手动 ZIP 安装，没有这次新增的一键下载功能。
**先安装一次 `BomberStudio_Blender_1.2.0_Universal.zip` 并重启**；之后遇到更高版本即可使用面板中的立即更新。
若当前已是最新正式版，立即更新按钮不会出现。
新检查结果有效期为 30 分钟，修改仓库或重新启动 Blender 后需要重新检查。

## 发布者怎样让按钮可用

在正式 Release 的 **Assets** 上传其中一种命名的真实安装包：

```text
BomberStudio_Blender_1.2.1_Universal.zip
BomberStudio_Blender_1.2.1.zip
```

这里只是下一版本的命名示例，不表示它已经发布。两者同时存在时优先选 Universal；
相同优先级存在重复候选时不猜测。不会把 GitHub 的 `Source code (zip)` 当成插件安装包，也不安装 master 源码快照。

Release 的 Tag 示例为 `v1.2.1` 或 `BomberStudio_Blender_1.2.1`。
以下三个字段必须实际为同一个版本：

```text
bomberstudio_blender/__init__.py        bl_info['version']
bomberstudio_blender/core.py            VERSION
bomberstudio_blender/blender_manifest.toml    version
```

**给 1.1.1 ZIP 改名为 1.1.2.zip 不等于升级到 1.1.2。**标签与内部版本不一致时，会停止更新且保留原插件。
使用项目的 `tools/build_release.py` 生成正确结构的 Universal ZIP，不打包 `__pycache__`。
遇到旧手工 ZIP 附带 `.pyc` 时，更新器只安装其源码，丢弃字节码缓存。

校验值优先使用 GitHub API 给出的附件 `digest`（SHA256）。
如果附件没有这个字段，需要在**同一个 Release** 上传打包脚本生成的 `SHA256SUMS.txt`，
其中必须有与附件文件名相符的唯一一行校验值。两者都缺少时，一键按钮会提示原因；仍保留发布页与本地 ZIP 入口。
修改 ZIP 名称后，校验文件中的文件名也必须对应；更稳妥的方式是不改脚本生成的名称。

## 取消、失败与回滚

- 仅检查不会下载 ZIP；只有用户点击并确认立即更新才下载和替换。
- 网络异常、下载中断、SHA256 不匹配、包内版本错误或 ZIP 路径不合规：不替换已安装插件。
- 替换目录或写入安装回执发生可恢复异常：尝试恢复原目录和上一次安装回执，错误写入日志。
- 下载与检查可取消；安装提交阶段不接受中途取消，以免留下半套文件。
- 同一插件正在更新时，另一更新事务会被锁挡住；异常退出留下锁时，先查看日志和备份，不要启动多个更新进程反复覆盖。
- 成功安装后，**还原上一次插件备份**可以恢复旧版代码；完成后也需重启。
- 这些备份恢复的是插件代码，不是模型；`.blend` 仍应自行保存。
- 断电或进程被强制终止不属于普通异常回滚；临时目录保留事务日志与备份，必要时据此手动恢复。

## 文件位置和限制

所有下载、暂存、日志与备份使用 **设置与诊断 → 临时 / 日志 / 备份目录**。
不要把这个目录设到插件安装目录内部。

```text
update-downloads/                 下载完成且通过 SHA256 的 ZIP
update-stage-*/                   解包后的待安装源码
addon-backup-*/                   旧版备份
last-update-check.json            最近一次成功检查
last-update.json                  本地/在线更新回执
update-journal-*.json             提交之前的恢复路径
bomberstudio.log                  状态和错误日志
```

为实现同卷目录替换，安装目录旁还会保留 `.bomberstudio-previous-*` 等事务目录。
回滚前不要手动删除这些目录。

- 元数据上限：2 MiB；压缩安装包上限：64 MiB；解包总量上限：64 MiB；单文件上限：8 MiB。
- 网络连接/读取超时：15 秒；ZIP 下载循环总时限：180 秒。
- 自动更新仅接受配置仓库的 GitHub HTTPS Release 附件，允许跳转到 GitHub 的附件存储主机。
- 功能沿用既有 Python 3.5 兼容层。旧 Blender 的 TLS、证书和本机网络环境仍可能影响在线连接；
  失败时有明确提示，并可继续使用本地 ZIP 安装入口。
